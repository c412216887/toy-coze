# Coze 平台 — MVP 后产品大纲

## 现状（MVP 已完成）

- 登录 → 工作流列表 → 拖拽编辑器（Start / LLM / End 三节点）→ 运行 → 实时流式输出

---

## Phase 1｜夯实基础体验

### 1.1 用户体系补全

| 功能 | 说明 |
|---|---|
| 注册页 | 前端入口，后端 API 已有 |
| 修改密码 | 基础账号安全 |
| 个人信息页 | 头像、昵称（可选） |

### 1.2 工作流运行历史

| 功能 | 说明 |
|---|---|
| 运行记录列表 | 每次 `/run` 持久化到 `t_workflow_run`，列表展示状态（running / success / failed）|
| 运行详情 | 查看历史输入、输出、耗时、token 用量 |
| 运行日志 | 节点级别的执行轨迹（节点名、耗时、输入输出）|

### 1.3 更多工作流节点类型

| 节点 | 用途 |
|---|---|
| HTTP 请求节点 | 调用外部 API，返回结果供下游节点使用 |
| 代码节点 | 内嵌 JS/Python 片段，数据清洗 / 转换 |
| 条件分支节点 | if/else，根据变量走不同路径 |
| 知识库检索节点 | 接入 Python RAG 微服务（后端已有，待前端接入）|

---

## Phase 2｜知识库（RAG）

> Python 微服务代码已有（`:8001`），前端和主后端尚未接入。

### 2.1 知识库管理

| 功能 | 说明 |
|---|---|
| 创建 / 删除知识库 | 一个知识库对应一个向量空间 |
| 上传文档 | PDF、Word、Markdown，解析 + 分块 + 向量化 |
| 文档列表 | 展示上传状态（处理中 / 完成 / 失败）|
| 文档删除 | 同步删除向量 |

### 2.2 工作流中使用知识库

- 知识库检索节点配置面板：选择知识库、设置检索 topK、相似度阈值
- LLM 节点支持注入检索结果作为上下文（system prompt 模板变量）

---

## Phase 3｜模型供应商管理

| 功能 | 说明 |
|---|---|
| 模型供应商列表 | OpenAI / Claude / 自定义 OpenAI-compatible |
| 添加 / 编辑供应商 | 配置 Base URL、API Key、可用模型列表 |
| LLM 节点选模型 | 配置面板从已配置的模型中选，不再硬编码 `DEFAULT_LLM_MODEL` |
| 连接测试 | 添加后一键测试连通性 |

---

## Phase 4｜Agent（对话机器人）

> 基于工作流，一键发布为可对话的 Agent。

| 功能 | 说明 |
|---|---|
| 创建 Agent | 绑定一个工作流作为对话 backend |
| 对话界面 | 内置聊天 UI，支持多轮对话（上下文管理）|
| Agent 设置 | 开场白、人设 prompt、头像 |
| 发布为 API | 生成对外调用的 API Key + Endpoint |

---

## Phase 5｜集成与发布

| 功能 | 说明 |
|---|---|
| Webhook 触发 | 外部系统 POST 触发工作流运行 |
| 工作流 API 发布 | 生成可外部调用的 REST API（带 Key 鉴权）|
| 定时触发 | Cron 表达式定时执行（Temporal Schedule）|

---

## Phase 6｜监控与运营

| 功能 | 说明 |
|---|---|
| Dashboard | Token 用量统计、运行次数、成功率趋势图 |
| 告警 | 运行失败发通知（邮件 / 钉钉 / 飞书 Webhook）|
| 多租户 / 团队 | 工作流按团队隔离，成员管理（后期）|

---

## 优先级汇总

```
Phase 1（当前冲刺）
  ├── 1.1 注册页          ← 2-3h，前端为主
  ├── 1.2 运行历史列表    ← 半天，前后端
  └── 1.3 更多节点类型    ← 1-2天（HTTP节点、条件分支最有价值）

Phase 2（知识库接入）     ← 后端代码已有，主要是前端+联调，1-2天

Phase 3（模型管理）       ← 中优先，涉及 LLM 节点重构，1天

Phase 4（Agent）          ← 高价值，依赖 Phase 1-3 完成，2-3天

Phase 5-6（集成/监控）    ← 后期
```

---

## 推荐下一步

**Phase 1.2（运行历史）+ Phase 1.3（HTTP节点 + 条件分支）+ Phase 2（知识库）**

三块拼起来 = 可演示的完整 RAG 工作流，比单纯 LLM 节点有说服力。
